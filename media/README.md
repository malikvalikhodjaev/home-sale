# Фотографии и медиа

## Принцип хранения

Оригиналы остаются на прежнем локальном месте и не меняются. Git хранит только индекс, решения об отборе и при отдельном решении — небольшие очищенные WebP-копии для публикации.

## Рекомендуемый поток

1. Сохранить оригинал без изменения.
2. Присвоить фотографии понятное назначение в `index.csv`.
3. Отметить чувствительные детали и допустимость публикации.
4. Создать отдельную рабочую копию.
5. Выполнить кадрирование, коррекцию и удаление лишних метаданных без сокрытия дефектов.
6. Экспортировать производную WebP-версию.
7. Связать WebP с конкретной версией объявления и публикацией.

## Что не помещать в Git

- оригинальные JPG, HEIC и PNG;
- фотографии документов;
- кадры с персональными данными, лицами без согласия, номерами документов и ключами;
- промежуточные дубли и автоматические экспорты;
- необработанные планы и PDF.

## Что можно добавить позднее

Только специально отобранные, очищенные и утверждённые WebP в `published/`. По умолчанию этот каталог пуст.
