# Структура репозитория по конфигурационным объектам

Структура отвечает не на вопрос «какой это тип файла», а на вопрос «какой объект продажи мы описываем и изменяем».

## Главные объекты

| Объект | Каталог | Что является конфигурацией |
| --- | --- | --- |
| Цели | `goals/` | источник истины в Coda и ссылка на принятую версию целевой конфигурации |
| Работы и пакеты | `work/` | источник истины в Coda и правила подтверждения результата |
| Продаваемый объект | `property/` | проверенные факты, состав и физические ограничения |
| Портреты покупателей | `portraits/` | проверяемые гипотезы совместимости, а не демографические стереотипы |
| Продукт-оффер | `descriptions/product-offer/` | состав предложения, цена, позиционирование и условия |
| Юридическое описание | `descriptions/legal/` | допустимые утверждения, раскрытия, блокеры и доказательства |
| Рекламные описания | `descriptions/advertising/` | тексты и снимки публикаций по версиям |
| Площадки | `platforms/` | роль канала, формат, активная публикация и правила измерения |
| Потенциальные покупатели | `leads/` | схема квалификации и этапы без персональных данных в Git |
| Сделка | `deals/` | этапы, условия перехода и обязательный gate безопасности |
| Метод | `methods/` | переиспользуемая процедура, её применимость, версия и доказательства |
| Роль | `roles/` | интересующие характеристики, полномочия и ожидаемый вклад участника |
| Локализация | `localizations/` | привязка общего паттерна к юрисдикции, источникам и окну актуальности |
| База знаний | `knowledge/` | проблемы, переносимые паттерны, исследования, ошибки и учебный маршрут |

## Поддерживающие объекты

- `market/` — аналоги и доказательства для ценовых решений.
- `media/` — индекс и конфигурация отобранных изображений.
- `operations/` — открытые решения и датированные срезы работы.
- `governance/` — общие правила характеристик, Q-Bundle, guardrails и версий.
- `governance/BEGINNER_ERROR_CONTROLS.md` — обязательные stop/go-контроли ошибок, применяемые к методам и задачам.
- `context/` — один короткий актуальный контекст.
- `sources/` — указатели на локальные и внешние исходники без их копирования.
- `scripts/` и `.github/` — локальная проверка и CI.
- `private/` — локальные снимки и инструменты, игнорируемые Git.

## Границы объектов

- `property` говорит, что истинно об объекте.
- `product-offer` говорит, что именно предлагается и на каких условиях.
- `legal` определяет, что можно утверждать и что необходимо раскрыть.
- `advertising` адаптирует принятый оффер для конкретной аудитории и площадки.
- `platforms` не хранит копию текста объявления: он ссылается на его версию.
- `portraits` описывает гипотезы сегментов; `leads` — реальные входящие случаи.
- `leads` и `deals` не содержат в Git ФИО, телефоны, адреса, паспорта, платёжные реквизиты или документы контрагента.
- предметный объект выбирает метод ссылкой на конкретную версию; процедура не копируется в каждый каталог;
- роль не равна человеку: один человек может исполнять несколько ролей, а одна роль — переходить между исполнителями; коллективное решение моделируется группой ролей, а не искусственной ролью «семья»;
- FPF и предметный DPF остаются переносимыми, а нормы Узбекистана находятся в отдельном квалификационном слое.
- база знаний описывает возможные решения; исполнимой конфигурацией решение становится только после выбора версии в `methods/`.
- ошибка из базы знаний становится исполнимым контролем только после связи с методом или задачей и определения evidence и stop/go-правила.

## Источники истины

| Данные | Основное место |
| --- | --- |
| Текущие цели, текущие и предпочтительные уровни | Coda «Стратегические цели продажи» |
| Датированные baseline-снимки | Git и история измерений |
| Задачи, исполнители, сроки и статус | Coda «Работы и задачи» |
| Версии конфигураций, текстов и решений | Git |
| Персональные данные покупателей и сделки | закрытая рабочая система, не Git |
| Оригиналы фото и юридических документов | локальное/закрытое хранилище, не Git |

## Именование и версии

- Новые файлы получают строчные латинские имена в `kebab-case`.
- Датированный снимок: `YYYY-MM-DD-<канал>-<назначение>.md`.
- Публикация неизменяема после фиксации в `published/`.
- Новая версия нужна при изменении фактов, цены, юридического раскрытия, существенного текста, состава имущества, набора медиа или целевой конфигурации.
- Новое измерение без изменения правила конфигурации отдельной версии не требует.

## Рабочий цикл

1. Решение или задача появляется в Coda.
2. Меняется один или несколько связанных конфигурационных объектов в Git.
3. Выполняется `./scripts/check_repository.ps1` и проверяется полный `git diff`.
4. Создаётся содержательный commit.
5. Ссылка на файл или commit возвращается в Coda как доказательство результата.
